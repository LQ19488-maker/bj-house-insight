## 1. 业务背景与系统目标

二手房交易中存在典型的三重信息不对称。**买方**面对的是几千条挂牌信息，缺少可比的参照系：同一套 80 ㎡ 的房子，在朝阳和房山差价可达 2.5 倍，但页面上只给出一个总价，买方无法判断"这个价在这个区位算贵还是便宜"。**卖方与中介**则倾向于用强属性叙事（"精装""近地铁""朝南"）制造溢价预期，而这些属性的真实溢价在未控制区位前根本无法验证——本项目的数据体检已经证明，房龄与单价呈正相关（r=+0.26）、塔楼比板楼贵 16.5%，这些反直觉结论正是"只看单属性会被误导"的直接证据。

**本系统解决的问题**有三个层次：第一层是**可比**，把 2890 条房源按区/街道/小区三级区位归位，任何一套房都能立刻回答"我在同区位处于什么位置"；第二层是**可验**，所有属性溢价都必须同时给出"全市口径"与"同区控制口径"两个数字，让读者看到差异中有多少来自区位；第三层是**可用**，把分析结论落到具体动作上——给定预算和需求做检索、给定条件做参考估价、给定同区样本识别性价比异常房源。

系统目标（可量化）：

| # | 目标 | 量化指标 | 验证方式 |
|---|---|---|---|
| G1 | 数据可对账 | 2890 行 100% 入库，行数漏斗自洽，5 个产物两次运行 MD5 一致 | `run-etl.cmd --roundtrip` |
| G2 | 查询可响应 | 列表查询 P95 < 300 ms；聚合分析接口 P95 < 800 ms | 压测脚本 50 次采样 |
| G3 | 结论可复算 | 看板每张图的数字都能被一条 SQL 独立复算，误差 0 | SQL 复核脚本 |
| G4 | 口径不漂移 | 字段名在 DDL / 接口 / 前端 / 数据字典四处同名 | `check_ddl.py` + 契约检查 |

## 3. 业务问题清单（12 条，全系统的灵魂）

每条问题的"实现依据"列即为可计算性证明；"混杂风险"列说明为什么不能只给单因子结论。

### Q1 各区价格水平差多少？价差主要由什么造成？　【P0】

| 项 | 内容 |
|---|---|
| 需要的指标 | 各区在售套数、均价、中位单价、中位总价、P25/P75 区间 |
| 需要的维度 | 所在区（17 个） |
| 呈现形式 | 横向条形图（均值 + 中位双标记，标注 n）+ 箱线图 |
| 实现依据 | `所在区`、`单价（元/平方米）`、`总价（万元）` |
| 实测锚点 | 西城 129,520 vs 平谷 23,072 元/㎡，**5.6 倍**；平谷仅 1 套、延庆 2 套 |
| 混杂风险 | **高**。必须标注样本量，n<3 的区不得进入排行结论 |

### Q2 市场供给集中在什么价位与面积段？　【P0】

| 项 | 内容 |
|---|---|
| 需要的指标 | 总价分桶计数与占比、面积分桶计数与占比、累计分布 |
| 需要的维度 | 总价区间、面积区间（由 `总价`/`面积` 实时分桶） |
| 呈现形式 | 直方图（分位分桶）+ 累计占比折线 |
| 实现依据 | `总价（万元）`、`面积（平方米）` |
| 实测锚点 | 总价中位 470 万、P25 320 万、P75 698 万；中位面积 81.3 ㎡ |
| 混杂风险 | 低。但**必须用分位分桶或对数轴**——总价 36–8000 线性分桶会全挤在前两格 |

### Q3 面积能在多大程度上解释总价？　【P1】

| 项 | 内容 |
|---|---|
| 需要的指标 | 散点、皮尔逊相关系数、线性回归斜率与截距、残差最大的 10 套房源 |
| 需要的维度 | 面积、总价；可选按区着色 |
| 呈现形式 | 散点图 + 回归线，标注 r 与 n |
| 实现依据 | `面积（平方米）`、`总价（万元）` |
| 实测锚点 | 面积–总价 **r = +0.719**；面积–单价 **r = −0.044** |
| 混杂风险 | 中。结论必须写成"面积解释总价，但**不解释单价**"，避免读者反过来解读 |

### Q4 房龄与单价是什么关系？在控制区位后是否仍然成立？　【P0】

| 项 | 内容 |
|---|---|
| 需要的指标 | 全市房龄段均价、分区的房龄段均价（同一张图多条折线）、区内相关系数 |
| 需要的维度 | 房龄段（0–5/5–10/…/40–50）、所在区 |
| 呈现形式 | 全市单线 + 分区多线对照图（**本系统的核心分析图**） |
| 实现依据 | `房龄`、`单价（元/平方米）`、`所在区` |
| 实测锚点 | 全市 **r = +0.260**；30–40 年 77,852、40–50 年 78,795 元/㎡ 为最高 |
| 混杂风险 | **极高**。这是典型辛普森悖论：老房集中在东西城核心区。**仅给全市单线即为误导** |

### Q5 地铁溢价值多少？其中多少是区位贡献？　【P0】

| 项 | 内容 |
|---|---|
| 需要的指标 | 全市 近/不近 地铁均价与溢价率、**各区内**溢价率、样本数 |
| 需要的维度 | 近地铁（0/1）、所在区 |
| 呈现形式 | 全市对比条形 + 分区溢价率分组条形（含样本量） |
| 实现依据 | `房源标签`（→`near_subway`）、`单价`、`所在区` |
| 实测锚点 | 全市 73,420 vs 57,609，**+27.4%**（方向可信，是本数据集最强的单因子） |
| 混杂风险 | **高**。近地铁房本身就集中在城区，区内对照后溢价必然收窄 |

### Q6 装修溢价值多少？是否被面积结构混淆？　【P1】

| 项 | 内容 |
|---|---|
| 需要的指标 | 各装修类型均价与中位价、相对基准组（简装）溢价率、**按面积段分层**的溢价率 |
| 需要的维度 | 装修（4 类）、面积段 |
| 呈现形式 | 溢价率柱状图（全市 / 分层两套口径并排） |
| 实现依据 | `装修`、`单价`、`总价`、`面积` |
| 实测锚点 | 精装 67,201 vs 简装 63,164，**+6.4%**；但毛坯单价最低（55,946）而中位总价最高（549.5 万） |
| 混杂风险 | **高**。毛坯多为大户型别墅，不分层会得出"毛坯更贵"的荒谬结论 |

### Q7 建筑结构（板楼/塔楼）对单价影响是否显著？　【P1】

| 项 | 内容 |
|---|---|
| 需要的指标 | 各结构均价、相对板楼的溢价率、同区控制后的溢价率、样本数 |
| 需要的维度 | 结构（5 类，其中平房/独栋各 1 条需合并或剔除）、所在区 |
| 呈现形式 | 分组条形（全市 vs 同区控制） |
| 实现依据 | `结构`、`单价`、`所在区` |
| 实测锚点 | 塔楼 71,219 vs 板楼 61,136，**+16.5%**（与常识相反） |
| 混杂风险 | **极高**。板楼混入大量远郊大盘与城区老公房；平房/独栋分母为 1 必须排除 |

### Q8 供给户型结构如何？不同户型单价差异多大？　【P1】

| 项 | 内容 |
|---|---|
| 需要的指标 | 户型 Top8 + 其他的套数与占比、各户型均价、室数分布、厅=0 占比 |
| 需要的维度 | 户型（25 种）、室（1–12）、厅（0–4） |
| 呈现形式 | 环形图 + 分户型均价条形 |
| 实现依据 | `户型`、`室`、`厅`、`单价` |
| 实测锚点 | 25 种户型；室 1–12、厅 0–4；`厅=0` 共 101 条（开间，非缺失） |
| 混杂风险 | 中。大室数户型样本极少（室=12 仅 1 条），排行需样本阈值 |

### Q9 楼层与朝向对单价有影响吗？影响多大？　【P2】

| 项 | 内容 |
|---|---|
| 需要的指标 | 各楼层层级均价、各朝向均价、朝南 vs 朝北溢价率、样本数 |
| 需要的维度 | 楼层层级（8 值）、朝向（8 方向，M:N 展开） |
| 呈现形式 | 小倍数图（facet）+ 溢价率标注 |
| 实现依据 | `楼层`（→`floor_level`）、`朝向`（→`house_orientation`）、`单价` |
| 实测锚点 | 朝南 61,404 vs 朝北 60,320，**+1.8%**（远弱于地铁 +27.4%） |
| 混杂风险 | 中。楼层"未知"占 364 条（12.6%），必须单列不得混入；朝向东/西样本仅 368/363 |

### Q10 哪些小区与街道价格最高、哪些最具性价比？　【P1】

| 项 | 内容 |
|---|---|
| 需要的指标 | 小区/街道 在售套数、均价、中位总价、同街道内分位；排行需样本阈值 |
| 需要的维度 | 小区（1865）、街道（264，**须排除 16 个伪街道组合**） |
| 呈现形式 | 排行表 + 街道内分位点图 |
| 实现依据 | `小区名`、`所在街道或镇`、`单价`、`总价` |
| 实测锚点 | 小区在售中位数 1 套，**67.4% 的小区仅 1 套**；最多 12 套 |
| 混杂风险 | **极高**。小区多半只有 1 个样本，**不能做箱线图**，只能做"在同街道中的位置" |

### Q11 给定预算与需求，能选到哪些房？　【P0】

| 项 | 内容 |
|---|---|
| 需要的指标 | 组合筛选（区/街道/价格/面积/户型/房龄/装修/结构/朝向/地铁）+ 排序 + 分页 + 结果计数 |
| 需要的维度 | 上述全部筛选维度 |
| 呈现形式 | 左侧筛选面板 + 右侧卡片/表格结果，支持 URL 分享 |
| 实现依据 | 全部 15 个入库字段 |
| 实测锚点 | 2890 条全量在浏览器内存中筛选为毫秒级 |
| 混杂风险 | 低。但排序必须字段白名单化，禁止拼接 |

### Q12 哪些房源是"性价比异常"？　【P0】

| 项 | 内容 |
|---|---|
| 需要的指标 | 同区 + 同面积段的单价分位、低于同组中位价 20% 以上的房源、偏离倍数 |
| 需要的维度 | 所在区、面积段、单价分位 |
| 呈现形式 | 异常房源表（含偏离倍数与同组样本数）+ 分位标尺 |
| 实现依据 | `所在区`、`面积（平方米）`、`单价` |
| 实测锚点 | 极值 72 行（P0.5–P99.5 并集）**只标记不删除**，其中西城 11 高、房山 10 低 |
| 混杂风险 | **高**。必须限定"同区同面积段"，否则全市口径下东西城会整片被标异常 |

## 6. 验收标准（Given-When-Then，10 条，覆盖 D1–D8）

| # | 场景 | Given | When | Then | 覆盖缺陷 |
|---|---|---|---|---|---|
| AC-1 | 尾随空格被清理 | 原始文件小区名 2890/2890 带尾随空格 | 执行导入 | `community.name` 无首尾空格；R1 修正单元格数为 **2892** | D1 |
| AC-2 | 冗余基线列被丢弃 | 装修"其他"列有 549 行为 True | 执行导入 | 该列不入库；`decoration` 仅 4 个枚举值；R2 触发计数 = 1 | D2 |
| AC-3 | 楼层残缺被正确标记 | 364 条楼层只有"18层" | 执行导入 | 这些行 `floor_level='未知'` 且 `floor_total=18`，**不得报错丢弃** | D3 |
| AC-4 | 朝向拆成多值 | 某房源朝向为"南 北" | 查询该房源朝向 | `house_orientation` 返回 2 行；按 `direction='南'` 能反查到它 | D4 |
| AC-5 | 派生区间不入库、异常户型保留 | 面积区间缺 3 行；"1室2厅" 12 条 | 执行导入 | 区间列不落库；12 条 `abnormal_layout=1` 且**行未丢失** | D5 |
| AC-6 | 单价一致性校验生效 | 任一房源 | 导入时校验 | `ABS(单价 − 总价×10000/面积) ≤ 1.00`；超容差行数为 **0** | D6 |
| AC-7 | 极值只标记不删除 | 总价 8000 万 / 面积 747.23 ㎡ 的房源 | 执行导入 | 该行仍在库中且 `is_outlier=1`；全库极值标记 **72** 行、删除 **0** 行 | D7 |
| AC-8 | 街道前缀错配被标记 | 海淀区下存在街道"昌平其他" | 查询该街道 | 返回 `is_pseudo=1` 且被记入 `data_quality_issue`（`pseudo_street_prefix_mismatch`），**不修改原文** | D8 |
| AC-9 | 伪街道不污染排行 | 16 个伪街道组合覆盖 107 行 | 请求街道排行（默认参数） | 结果中不含任何 `is_pseudo=1` 的街道；显式传 `include_pseudo=true` 才出现 | D8 |
| AC-10 | 越权与非法参数被拒 | 以 user 角色 | 请求 `POST /api/v1/admin/import`；或请求 `?sort=drop table` | 分别返回 `2003 权限不足` 与 `1002 非法排序字段`，**均不返回 500** | NFR 安全 |
